## 3. Commands / tools used
- `git status` - shows which files are changed
- `git add README.md` - stages the file for the next commit
- `git commit -m "message"` - saves the staged changes
- `git log --oneline` - shows past commits
- `git checkout -b update-about` - creates and switches to a new branch
- `git push -u origin update-about` - uploads the branch to GitHub
- `git switch main` and `git pull` - go back to main and get the latest changes
- VS Code, GitHub website


## 4. My understanding
- Staging means choosing the changes. Committing means actually saving them. So `add` picks, `commit` saves.
- A branch is a separate copy of the work where I can make changes without touching `main`.
- A Pull Request asks to merge my branch into `main` so others can check it first.
- When many people work on one project, branches stop us from overwriting each other, and PRs help catch mistakes.
